# Replit Prompt — Build a Full Result Indexing Tool for Algorithm Testing

Build an internal developer tool in this Replit app called **Indexing Tool** that allows me to ingest, paginate through, normalize, store, and inspect **all available results** from my funding data sources instead of only using the first 26 results.

## Main problem to solve

Right now the app is only using a small subset of records, around 26 results, which is not enough for accurate algorithm testing.

I need a tool that:

* fetches **all pages / all batches** of results from each source
* keeps requesting data until there are no more results
* stores the normalized records in a central indexed store
* prevents duplicates
* lets me inspect how many total records were fetched from each source
* makes the full indexed dataset available to the Algorithm V1 testing page

## Scope of indexing

I am using these 11 total sources:

### Active opportunity sources to index for V1 testing

* Simpler Grants
* Grants.gov Search
* SAM.gov Opportunities
* SBIR
* 360Giving
* California Grants Portal
* World Bank Procurement
* TED (EU)

### Historical / intelligence sources that may also be indexed but must be flagged separately

* USAspending
* NIH RePORTER
* NSF Awards

The indexing tool should support all 11 sources, but it must classify each record as either:

* `active_opportunity`
* `historical_intelligence`

This way the Algorithm V1 page can pull only active opportunities.

## Primary objective

Build a reusable indexing pipeline that retrieves **all results**, not just the first page, and stores them in a unified normalized structure for downstream matching tests.

Each indexed record should contain:

```ts
{
  id: string,
  source: string,
  sourceRecordId: string,
  classification: 'active_opportunity' | 'historical_intelligence',
  title: string,
  description: string,
  agency: string | null,
  fundingType: string | null,
  status: string | null,
  openDate: string | null,
  closeDate: string | null,

  categories: string[],
  keywords: string[],
  geography: string[],
  url: string | null,
  rawPayload: any,
  normalizedAt: string,
  dedupeKey: string
}
```

## Dedupe requirements

Prevent duplicates across reruns.
Create a `dedupeKey` using a combination like:

* source + sourceRecordId
  or
* source + title + closeDate
  if source record IDs are inconsistent.

On re-index:

* skip exact duplicates
* optionally update changed records
* preserve counts for inserted vs updated vs skipped

* no results remain
* there is no next page token
* the returned batch is empty

Default testing values should be generous, for example:

* max pages: 1000
* max records: 100000
