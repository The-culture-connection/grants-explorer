# Replit Prompt — Implement Algorithm V2 Using Real Indexed Data Only

Build **Algorithm V2** in this Replit app by extending the existing V1 funding-match system, the real indexed data pipeline, and the existing audit/debug tooling that are already implemented in the project.

## Core requirement

This V2 implementation must **build on top of the current codebase**. Do not replace the current system from scratch.

Use what already exists:

* the current V1 matcher
* the real indexed data store
* the source filtering/classification logic
* the Algorithm page
* the Indexing Tool
* the Algorithm Audit tooling
* any existing normalization logic
* any existing organization profile inputs and opportunity schemas

## Strict data rule

Use **real indexed data only**.

Do **not** introduce, seed, or rely on any mock data, fallback sample data, demo fixtures, or hardcoded toy opportunities/organizations anywhere in the V2 matching path, audit path, comparison path, or UI.

If data is missing, surface that clearly in the UI instead of inventing records.

## Goal

Improve ranking quality so that results are based on **true practical fit**, not just broad topic similarity.

V2 should work broadly across many organization types, not just one example.

It must improve matches for organizations such as:

* nonprofits
* small businesses
* universities
* local governments
* tribal organizations
* research institutions
* community-based organizations
* contractors
* international NGOs

## Important source rule

V2 matching and displayed opportunity rankings must continue using only **active opportunity** records from the indexed store.

Include only these active-opportunity sources in rankings:

* Simpler Grants
* Grants.gov Search
* SAM.gov Opportunities
* SBIR
* 360Giving
* California Grants Portal
* World Bank Procurement
* TED (EU)

Do not rank these as live opportunities:

* USAspending
* NIH RePORTER
* NSF Awards

Those historical/intelligence sources may remain available for future analytics or benchmarking, but they must not appear as current opportunity results in V2 rankings.

# Main V2 design

Implement V2 as a **generalized profile-to-profile matcher**.

Instead of relying mostly on raw keyword overlap, V2 should compare:

* a normalized, inferred **organization profile**
  against
* a normalized, inferred **opportunity profile**

The final score should reflect:

* relevance
* practical fit
* operational realism
* scale appropriateness
* organization/opportunity type compatibility
