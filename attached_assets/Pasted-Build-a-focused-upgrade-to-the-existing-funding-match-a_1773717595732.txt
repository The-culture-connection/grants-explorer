Build a focused upgrade to the existing funding-match algorithm to improve ranking quality without rebuilding the app.

IMPORTANT:
- Extend the current system; do not replace it from scratch.
- Preserve V1 and the existing V2 implementation for comparison.
- Use the existing real indexed data store only.
- Do not add mock data, sample data, demo records, or fallback fixtures.
- Do not change the indexing pipeline unless needed to expose missing source counts or fix a real query limit.
- Keep all existing audit/debug pages and extend them.

MAIN GOAL:
Fix the ranking logic so the matcher rewards highly specific, truly relevant opportunities and stops over-ranking generic, loosely related opportunities.

CONTEXT / OBSERVED PROBLEMS:
The current audit suggests:
1. The app is scoring the full database, then only displaying a top subset, so the main problem is ranking quality, not traversal.
2. Eligibility is too permissive; nearly everything is passing.
3. Generic overlap terms like "health", "community", and "support" are being rewarded too much.
4. Broad opportunities are outranking specific opportunities.
5. Several dimensions are too easy to max out, especially geography, capacity, and funding.
6. The algorithm does not distinguish enough between:
   - exact/high-value phrase matches
   - broad domain adjacency
   - intended applicant type
   - target population specificity
7. A likely corpus issue may exist if some intended sources are missing from the scored-source breakdown.

BUILD A TARGETED RANKING FIX WITH THESE FEATURES:

==================================================
1. ADD EXACT-PHRASE PRIORITY SCORING
==================================================

Implement a phrase-priority layer that gives significantly more weight to exact or near-exact phrase matches than to broad token overlap.

Examples of high-value multi-word phrases:
- maternal health
- birth equity
- Black maternal health
- pregnant people
- reproductive health
- public health workforce
- clean energy
- sustainable technology
- workforce development
- affordable housing
- violence prevention
- small business support

Requirements:
- phrase matches should outrank generic unigram overlap
- exact phrase matches should receive a strong bonus
- semantically close phrase variants can receive a smaller bonus
- a result with one or two strong exact concept matches should beat a result with many weak generic word overlaps

Add reusable helpers like:
- extractHighValuePhrases(text)
- computePhrasePriorityScore(orgProfile, oppProfile)
- detectExactConceptMatches(orgConcepts, oppConcepts)

==================================================
2. ADD GENERICITY PENALTY
==================================================

Implement a penalty for results that score mostly because of broad, low-information words.

Examples of overly generic terms that should be strongly downweighted unless part of a meaningful phrase:
- health
- community
- support
- outcomes
- improve
- innovation
- services
- equity
- development
- research

Requirements:
- generic words alone should not drive top rankings
- if the score is built mostly from generic overlap, apply a penalty
- if generic words appear inside a strong recognized concept phrase, do not penalize as heavily

Add helpers like:
- isGenericTerm(token)
- computeGenericityPenalty(scoreTrace)
- computeSignalSpecificityRatio(scoreTrace)

==================================================
3. MAKE ELIGIBILITY A TRUE GATE AGAIN
==================================================

The current eligibility behavior appears too permissive.

Implement stricter eligibility handling:
- parse applicant-type constraints more carefully
- treat clear incompatibilities as exclusion, not just a lower subscore
- surface explicit eligibility failure reasons

Examples of applicant type distinctions:
- nonprofit
- small business
- university / higher education
- research institution
- HBCU / MSI-specific
- healthcare provider
- government agency
- tribal organization
- contractor / vendor
- international NGO

If the opportunity explicitly targets a group the organization clearly is not, exclude it before ranking.

Add helpers like:
- parseApplicantTypeConstraints(opportunity)
- inferOrganizationApplicantType(org)
- passesStrictEligibility(orgProfile, oppProfile)

Update the audit page to show:
- eligibility hard-fail count
- top eligibility failure reasons
- examples of excluded records

==================================================
4. ADD TARGET-APPLICANT FIT
==================================================

Create a new scoring dimension for intended recipient fit.

This is separate from eligibility.
An org may technically be eligible but still not be the intended applicant.

Examples:
- HBCU-only or higher-ed-centered opportunity should not rank highly for a community nonprofit
- procurement opportunity should not rank highly for an advocacy nonprofit
- research-center opportunity should not rank highly for a service-oriented small nonprofit

Infer intended applicant from:
- title
- description
- eligibility text
- source metadata
- funding type
- known opportunity-type patterns

Add a new score:
- targetApplicantFitScore

And a penalty:
- targetApplicantMismatchPenalty

==================================================
5. REBALANCE DIMENSIONS SO EASY POINTS DO NOT DOMINATE
==================================================

The current scoring appears too generous on:
- geography
- capacity
- funding
- org type

Adjust the weighting and scoring behavior so these dimensions support ranking but do not overwhelm core relevance.

Requirements:
- geography should not give full points too easily
- capacity should not default to near-max unless there is real evidence
- funding should be modest and not rescue weak matches
- org type should be meaningful but not enough to push a weak topical match into the top tier

Recommended approach:
- reduce easy-max dimensions
- increase the influence of specificity, intended applicant fit, and exact concept fit

Keep weights configurable.

==================================================
6. ADD CONCEPT CENTRALITY SCORING
==================================================

Implement a way to detect whether the opportunity is centrally about the organization’s core concepts, not merely adjacent.

Example:
If the organization is about "maternal health", then:
- title-level and repeated concept presence should matter more than one passing mention in the description
- target population alignment should matter more
- activity alignment should matter more

Create a score that rewards:
- concept in title
- concept in summary/opening text
- repeated concept presence
- concept paired with the right population or activity model

Add helpers:
- computeConceptCentrality(orgProfile, oppProfile)
- computeTitleMatchBonus(orgProfile, oppProfile)
- computePopulationSpecificityBonus(orgProfile, oppProfile)

7. ADD TARGET-POPULATION SPECIFICITY
==================================================

The current population score is too broad.

Improve it so that:
- “Black women” is more specific than “minorities”
- “pregnant people” is more specific than “women”
- “families” is more specific than “community members”
- “public agencies” is different from “general population”

Requirements:
- more specific aligned populations should outrank broader umbrella populations
- broad umbrella terms can still count, but less strongly
- if there is a mismatch between intended beneficiary groups, add a penalty

Add helpers:
- normalizePopulationTags(text)
- computePopulationSpecificity(orgProfile, oppProfile)
- computePopulationMismatchPenalty(orgProfile, oppProfile)
